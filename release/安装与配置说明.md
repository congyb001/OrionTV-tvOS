# OrionTV Apple TV 客户端 — 安装与配置说明

## 产物信息

| 项目 | 值 |
|---|---|
| 文件 | `OrionTV_1.3.14_AppleTV.ipa`（8.7 MB） |

## 安装方式一：Sideloadly（推荐，全程图形化）

1. Mac 上下载 Sideloadly（https://sideloadly.io ），支持 tvOS。
2. Apple TV 与 Mac 连同一个局域网；在 Apple TV 上打开
   `设置 → 遥控器与设备 → 远程 App 与设备 → 遥控器与 Apple TV 配对` 旁的“无线调试/Remote
   App & Devices”，确保 Apple TV 允许远程安装（新版 tvOS 用 Xcode 签名安装即可自动发现设备）。
3. 把 `OrionTV_1.3.14_AppleTV.ipa` 拖进 Sideloadly，Apple 账号填你的 Apple ID（或 App 专用密码）。
4. 选择目标设备为你的 Apple TV（会显示 IP），点 Start。
5. 安装完成后，第一次启动 App 前需在 Apple TV 上信任开发者：
   `设置 → 通用 → 关于 → 证书信任设置` 里信任你的 Apple ID 证书（部分 tvOS 版本在
   `设置 → 通用 → 设备管理`）。
6. 免费 Apple ID 的证书 7 天后失效，届时 App 会闪退，用 Sideloadly 重新签一次即可
   （已登录的服务器配置会保留）。

## 安装方式二：Xcode 直接装（可免 Sideloadly，也能自由改代码）

1. 打开工程：`OrionTV/ios/OrionTV.xcworkspace`（注意是 workspace，不是 xcodeproj）。
2. Xcode 顶部 `Signing & Capabilities` → Team 选你的 Apple ID，Bundle ID 可改成唯一值
   （如 `com.你的名字.oriontv`，避免与他人冲突）。
3. 顶部运行目标选你的 Apple TV（需同一局域网，且 Apple TV 已开启“遥控 App 与设备”配对），
   点 Run 即可安装到真机。
4. 想改界面/功能，直接改 `OrionTV/app`、`OrionTV/components` 下的 TSX，重新 Run 生效。

## 首次启动配置（必须做）

App 本身不带片源，是**纯前端**，需要接一个后端聚合服务（MoonTV / LibreTV 类服务）。
上游 README 明确：1.2.x 以上版本需配合 MoonTV 使用。

1. 打开 OrionTV，首页会提示“请点击右上角设置按钮，配置您的服务器地址”。
2. 右上角齿轮 → 「API 配置」里填写服务器地址，例如 `http://192.168.1.10:3000`
   （只填 IP 时 App 会自动补 `http://` 或 `https://`）。
3. 电视上打字很痛苦，设置页内置了「远程输入」：用手机扫页面上的二维码 / 打开其中的
   局域网地址，在手机上输入地址后会自动回填到电视。
4. 保存后回首页，出现「最近播放 / 热门剧集 / 电视剧 / 电影 / 综艺 / 豆瓣 Top250」
   分类即代表连接成功。
5. 「直播」页可单独配 M3U 直播源地址（与 API 地址分开填）。

## 这次编译针对新版 Xcode 做的 4 处适配

本地是 Xcode 27.1 + tvOS 27.0 SDK，上游工程默认按老版本配置，直接编译会失败，改动如下
（已保存在 `OrionTV/ios/` 里，改完可重复构建）：

1. **部署目标 13.4 → 15.0**
   `ios/Podfile` 的 `platform :tvos` 常量、`ios/Podfile.properties.json` 增加
   `ios.deploymentTarget`、`OrionTV.xcodeproj` 的 `TVOS_DEPLOYMENT_TARGET`。
   原因：Xcode 27 只支持 tvOS 15.0 ~ 27.0 的部署目标，低于 15.0 直接报错。
2. **Podfile 加 post_install 统一抬升所有 Pod 的 `TVOS_DEPLOYMENT_TARGET`**
   原因：react-native-tvos 各 Pod 自己写死 13.4/12.4，逐个改不现实。
3. **`ios/.xcode.env.local` 固定 `NODE_BINARY`**
   默认生成的是带空格的路径（`.../Application Support/...`），Hermes 的脚本阶段没加引号，
   会在 `Replace Hermes for the right configuration` 这一步报
   `No such file or directory`。改成 `/opt/homebrew/bin/node` 即解决。
4. **GitHub 克隆走镜像**
   pod install 时克隆 CocoaAsyncSocket 等仓库会因 HTTP2 层错误失败，
   已配置 `git config --global url."https://ghfast.top/https://github.com/".insteadOf "https://github.com/"`。
   （如果以后不想要这个全局配置，可删：`git config --global --unset-all url.https://ghfast.top/https://github.com/.insteadof`）

## 设置页稳定性修复（重要）

上游代码里「设置」页有两处平台强依赖，已在本地修掉，当前 ipa 与源码都是修复后的版本：

1. **`useTVEventHandler` 在非 TV 平台是 undefined**
   上游 7 个文件直接 `import { useTVEventHandler } from "react-native"`，react-native-web 没有这个
   API，一点设置页就报 `useTVEventHandler is not a function` 并整页崩。
   现统一改为 `utils/tvEventHandler.ts` 封装：有该 API 就用原生实现，没有就退化为空订阅，
   TV 上行为完全不变。
   （涉及 `app/settings.tsx`、`app/live.tsx`、`components/settings/` 下 4 个分区、
   `hooks/useTVRemoteHandler.ts`）

2. **`inputRef.current?.setNativeProps` 在 web 的 TextInput 上不存在**
   地址输入框聚焦时会报 `setNativeProps is not a function`。
   已改为先判断 `typeof setNativeProps === "function"` 再调用
   （`APIConfigSection.tsx`、`LiveStreamSection.tsx`）。

验证结果：
- tvOS 模拟器：设置页正常渲染（远程输入状态、API 地址、直播源地址、保存设置全部在）。
- 浏览器（web）：进入设置 → 输入地址 → 保存，全流程无崩溃；服务器不可达时正常提示
  “请检查网络或者服务器地址是否可用”，不会抛异常。

## 已知限制

- App 内“检查更新”走的是 Android APK 的下载链接（上游只发 APK），在 Apple TV 上点了
  不会有实际更新动作，忽略即可，更新靠重新打包。
- 未签名 ipa 不能直接双击安装；必须经 Sideloadly / Xcode / AltStore 之一签名。
- 上游采用 React Native，播放器为 expo-av；部分片源的 HLS/MP4 编码在 tvOS 上可能不支持，
  这类问题属上游能力边界。
